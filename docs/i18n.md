# The page's words: messages, locales and the text editor

Every string a visitor reads (labels, hints, aria labels, the guide, the chronicler's stories, card text,
errors, the page's meta tags) is a **message**: an id and its source text in
[ICU MessageFormat](https://formatjs.github.io/docs/core-concepts/icu-syntax), the syntax FormatJS, Crowdin,
Weblate, Lokalise and Unicode's MessageFormat 2 grew from. The source text stays in the code, where it is
used, so the code still reads as what it shows; `tools/i18n/extract.mjs` reads it all into `locales/en.json`.
A **locale** is a catalog of the same ids in other words: a translation, or the viewer's own rewrite of the
English (`locales/en-x-rewrite.json`, made in the text editor).

## In code

```js
import { tr } from './i18n.js';
el.textContent = tr('dock.pause', 'Pause');
el.innerHTML = tr('spec.age', 'Age <b>{age}</b> of {span}', { age: fmtDur(a), span: fmtDur(life) });
// i18n: {name} is a species' name (a link); {n} cells
tr('chron.boom', '{name} thrives: {n, plural, one {# cell} other {# cells}} now.', { name: L(reg, s), n: sp.pop });
```

- **`tr(id, message, values)`**. The id and the message are literals (the extractor reads them; a dynamic
  id or message fails the build). `values` holds every `{argument}` and every non-HTML `<tag>`.
- **Ids**: `area.thing[.part]`, lowercase, words joined by `-`: `rail.light`, `spec.tab.genome`,
  `chron.obit.line-endures`. The area is where it shows (`rail`, `dock`, `settings`, `bench`, `spec`, `mind`,
  `lab`, `census`, `guide`, `gloss`, `chron`, `card`, `film`, `worlds`, `menu`, `err`, `ach`...). Name
  what a message is for, never its words (the words will change). One id is one message: two places
  that show the same words for the same purpose share an id; the same words for different purposes get
  two ids (a translator may need them to differ).
- **Whole sentences**. Never build text from translated fragments (`'was ' + verb + ' by ' + name`): word
  order, articles and agreement differ between languages, and a rewrite needs the whole sentence in view.
  A sentence with parts that vary is one message with arguments, `{x, select, ...}` for the variants and
  `{n, plural, one {...} other {...}}` for counts (the number itself, not a formatted string: `#` prints
  it in the locale's digits). A list (`a, b and c`) is `Intl.ListFormat`. When a sentence has too many
  variants for one message, make each variant its own whole message.
- **Articles and plurals come from the message, not from code**: no `/^[aeiou]/.test(w) ? 'an' : 'a'`, no
  `` `cell${n === 1 ? '' : 's'}` ``, no `.toLowerCase()` or `Cap()` of a translated word. Give the message
  the noun's key (`{guild, select, producer {a producer} ...}`) or a message for each form.
- **Logic never reads text.** Compare keys, kinds and numbers, never what a message said (`shareWords(x)
  === 'a few'` breaks the moment the words change, and in the editor's marked build at once).
- **Markup**: a message for innerHTML may hold plain inline tags (`<b>`, `<i>`, `<kbd>`, `<small>`,
  `<span>`), which come out as themselves. Markup with attributes is a named tag the call supplies:
  `tr('x', 'Its <term>diet</term>', { term: (c) => term('diet', c) })`. Values go in unescaped, as in the
  template literals they replace: escape names with `esc()` as before.
- **Not messages**: species and genus names (generated; `translate="no"`), glossary keys (`data-tip`),
  ids, classes, storage keys, event names, console output, errors thrown for developers, WGSL, the
  headless tools' output. A string the audit flags that is none of these but must stay as it is gets
  `// i18n-ignore` on its line (or `// i18n-ignore-next` on the line above).
- **Notes**: a comment holding `i18n:` on the line or two above a call is shown with the message in the
  editor and to translators. Say what each argument is when it is not obvious, and where the text sits
  if the code does not make it plain.
- **Tables of labels** are built at load: `const NAME = { grazer: tr('guild.grazer', 'Grazer'), ... }`.
- **Changing English**: a message whose words change keeps its id (the editor and any catalog follow it);
  a new purpose gets a new id. Never name a local variable `tr` (it shadows the import and the extractor
  reads the wrong calls).
- **Numbers**: a plain `{n}` prints as given (`12345`); a plural's `#` is formatted for the locale
  (`12,345`). Pass `fmt(n)` as a plain argument, or use `#`, to keep what the text printed before.
- **Capitals**: text shown in capitals (the live annotations' HUD) is written in capitals in its message;
  a key the code holds (a guild, a form, a cause) becomes words through a `select`, never `toUpperCase()`.
- **The audit is a net, not a proof**: it finds prose by shape and misses single words and short labels
  (`'Off'`, `'KILL'`, `'Current'`). Look over every visible literal in what you add.
- **A new area** (the id's first part) gets a heading in the editor's list: `AREAS` in
  `tools/i18n/textlab/app.js`.

After adding or changing messages: `node tools/i18n/extract.mjs`, commit `locales/en.json` with the change,
and `node --test test/i18n.test.js`.

In `src/page.html` an element marked `data-i18n="id"` holds message `id` (its words, with inline elements
as tags: `<kbd>K</kbd><span>Field</span> Lab`; a tag that repeats is numbered, `<a1>`, `<a2>`) and each
translatable attribute it carries as `id.aria` (aria-label), `id.hint` (data-hint), `id.alt`, `id.ph`
(placeholder), `id.title`; a `<meta>`'s content is `id` itself. An element with only attributes may hold
marked elements of its own. The build bakes a locale's words into those spans (`tools/i18n/html.mjs`).

## Tools

- `node tools/i18n/extract.mjs` writes `locales/en.json` (committed) and `locales/context.json` (where each
  message is used, for the editor; not committed); `--check` fails when en.json is stale; `--audit` lists
  prose in the source that does not go through `tr()`. `test/i18n.test.js` runs both.
- `node build.mjs --locale L` builds the page in locale L's words to `dist/tidemote.L.html`; `--locale en-XA`
  is the pseudo-locale (every letter accented, a third longer, bracketed: plain English left on the page is
  text the catalog does not reach, and what overflows will overflow in German); `--mark` marks every
  message with its id in invisible characters (`dist/tidemote.marked.en.html`, the text editor's page).
- `TIDEMOTE_VK=1 tools/capped.sh -m 900M node tools/i18n/tour.mjs --page FILE --out runs/i18n/NAME`
  drives a build through its states (intro, menu, every Settings and Lab tab, a species and a cell in the
  specimen panel, the card, help, bench, ladder; laptop and phone) and records every string it shows,
  canvases' too; `--shots` adds a screenshot of each state. `tools/i18n/textdiff.mjs A B` compares two
  tours (numbers and names masked): the source build must show what the build before it showed.
  `tools/i18n/coverage.mjs runs/i18n/XA` lists what a pseudo-locale tour shows that is not pseudo.

## Rewriting the English (the text editor)

The viewer's own rewrite of the page's English is a locale like any other, `en-x-rewrite`, made in the text
editor and checked before it replaces the source:

1. **Rewrite.** `npm run text` serves the editor at http://localhost:4711. Messages are listed in the order a
   visitor meets them, by area, filtered by state (To do, Draft, Done, Needs a look, Approved) or searched.
   Each shows its original (values as chips: click one to insert it), where it sits (screenshots from a
   marked tour with the message outlined; the code that uses it, what it fills: visible text, hover hint,
   screen reader label, canvas...), any note, and how the new text reads in each plural and select case.
   Every keystroke is saved after a pause: the text into `locales/en-x-rewrite.json` (only what differs),
   its state and last versions into `locales/review/en-x-rewrite.json`, and each save appended to
   `locales/review/en-x-rewrite.journal.jsonl`; an edit the server has not confirmed waits in the browser and
   goes again. Ctrl+Enter marks a message Done, Ctrl+K keeps the original; both move on. The Live page tab is
   the page in the rewrite's words (Rebuild with my text): Alt-click any text there to open its message.
   Capture takes the screenshots (`tools/i18n/tour.mjs --shots` on a `--mark` build into `runs/i18n/shots`,
   ten minutes or so; under WSL through `tools/gpu-node.sh`). Take them again after the page changes.
2. **Review.** `npm run text:review` checks every Done message in its current words: structure
   (`tools/i18n/check.mjs`: it parses; it uses only values the code gives; it keeps tags, a hint's key after
   ` · `, its edge spaces and line breaks; a short label in a fixed box does not grow much) and spelling and
   grammar (Harper, offline, American English; every word the source already uses is accepted). Findings
   show beside the message; one with an open finding is flagged. Then a reader (Claude) reads what is left
   (`--list checked`) for sense: against what the page does, the glossary's terms, the rest of the rewrite's
   voice; and approves (`--approve ID...`) or adds a finding (`--note ID "..." --suggest "..."`). The viewer
   answers a finding in the editor (Use suggestion, Fixed, Keep mine); an edited message goes back through.
3. **Promote.** `npm run text:promote` writes every approved message into the source (the literal in each of
   its `tr()` calls, its span in page.html), extracts en.json again and takes it out of the rewrite. Then
   build, run the tests, and tour the new build against the old one: `textdiff` should list exactly the
   promoted messages.

A translation goes the same way without step 3: `locales/de.json` (say) beside en.json, built with
`node build.mjs --locale de`. Weblate, Crowdin and Lokalise read these files as "simple JSON" with ICU
messages; `locales/context.json` holds what a translator should know about each.
