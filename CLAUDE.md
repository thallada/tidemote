# Tidemote

GPU biosphere simulation (WebGPU, WGSL) with a browser page and headless tools. See README.md for the design.

## Commands

- `npm run build` bundles `src/` with esbuild into the single-file `dist/tidemote.html`.
- `npm test` runs unit tests (`test/*.test.js`) and a short headless smoke sim.
- `node tools/sim.mjs --chrome --n 4096 --minutes 5 --out run.json` runs the page's ecology headlessly and writes JSON metrics.
- `node tools/compare.mjs --chrome --seeds 3 --minutes 5 --n 4096 --jobs 3 --out runs base '{}' variant '{"k":{"bite":0.4}}'` compares configurations across seeds.
- `npm run gate -- --out runs/NAME --k '{...}'` (32 seeds × 30 min at 32k against `balance/baseline-32k-30m.json`, ~16 min) is the balance regression gate (see docs/headless-gpu.md). Run it before and after any ecology change.
- `npm run gate:farm -- --out runs/NAME --k '{...}'` runs the same gate with seeds spread over every GPU machine in `~/.config/tidemote/farm.json` (`tools/farm.mjs`: one commit in a worktree per host, a shared queue, per-machine slots; docs/headless-gpu.md).
- `tools/gpu-node.sh tools/fork.mjs --k '{"diag":1}' --variants '[{"name":"m1","step":1},{"name":"m4","step":4}]'` runs matched-start forks: one world, the same moment run forward under several step lengths or tunables, pair by pair (summaries in `tools/fastforward/`). With `{"diag":2}` the ledgers count producers by body form and `python3 tools/fastforward/forms.py runs/X/*.json` shows which forms a step length favors (growth, births, deaths, energy, torn bonds, packing) in minutes rather than long runs. `--step N` on `sim.mjs`/`ensemble.mjs` runs coarse steps; `sim.mjs --profile` times each pass.
- `tools/gpu-node.sh tools/perf/bench.mjs --plan tools/perf/plans/baseline.json --out runs/perf/x.json` profiles the built page in Windows Chrome on the GPU (saved worlds, every pass timed); see docs/performance.md. Settings → Performance → Copy profile does the same on any device. `--android` runs a plan in Chrome on a phone connected to adb (USB through Windows' adb with gpu-node.sh, or Wireless debugging; docs/performance.md, Phones and Tools).
- `tools/adreno/regs.sh sim senseMain lifeMain senseMain:COARSE=1 lifeMain:COARSE=1` prints what each compute kernel holds at its widest moment on an Adreno 630 (vec4 registers of 48, the waves of threads resident), by Mesa's compiler on a pretended one (plain `node`; Mesa built once, tools/adreno/README.md). A phone's speed follows it (docs/performance.md, The step in two kernels): check after changing `senseMain`, `lifeMain` or `cellWGSL` that none spills (48); under that the phone does not follow its count, so measure a rewrite there.
- `tools/gpu-node.sh tools/ui-audit.mjs --out runs/ui/NAME` screenshots the built page at laptop and phone sizes and audits it (text under 11px, targets under 24px, the specimen compass above the fold, axe-core); `--page FILE` audits an older build. `tools/ui-check.mjs` drives the census-chart toggle and the Settings volume slider. `tools/menu-check.mjs` drives the opening menu as a visitor meets it (the page lets an automated browser's intro go by itself, so the others never see it): a count or a save chosen while the GPU is measured, Escape, keys that do and do not begin, the panels fitting a phone. `TIDEMOTE_VK=1 tools/capped.sh node tools/lineage/nav-check.mjs runs/lineage/wA/t00072m.json` drives the Lab's Lineage view on a captured world (`tools/lineage/capture.mjs`): rows and bands that explore, the reticle and the line of descent that show a species in the water, breadcrumbs, the span chip, Esc and Backspace, at a laptop's size and a phone's. Run them after UI changes.
- `tools/gpu-node.sh tools/swimlab.mjs --body filament:12 --sweep '[{"beat":[0.5,1.5,1,1]}]'` builds one body (`filament:N`, `branch:N:EVERY:LEN`, `mat:N:TAILLEN:TAILS`) alone in still water and measures its swimming against resistive force theory (`--step 4` for coarse steps, `--grow` to let it bud); docs/growth.md. Check beat or tail changes with it at 1 and 4 ticks.
- `tools/gpu-node.sh tools/steplab.mjs --body filament:5 --genome '{"beat":[0.5,1.5,0.8,1]}'` runs one coarse step and the 1/60 s steps it stands for from the same moments across a beat and prints each cell's error (docs/fast-forward.md, Beating bodies). Check changes to how coarse steps move bodies (`bodyTick`, `lifeMain`'s coarse paths) with it; a real tailed mat needs `--genome '{"grow":[0,0.3,0,0.5,0,0],"tail":[1,0.3],...}'` (the test genome grows trees).
- `tools/gpu-node.sh tools/ridelab.mjs --body mat:19:4:2 --stone 1` rides one body alone in still water (tools/swimlab-bodies.mjs) by a script of held ways and measures its bonds, its speed as a way is held, a tap's reach and a wall of stone; `--old DIR` rides it as a source tree DIR (a worktree of an earlier commit) did. `TIDEMOTE_VK=1 tools/capped.sh node tools/ride-check.mjs` drives riding on the built page (one Ride button, the camera's dive and breathing, WASD, a scroll, getting off, Ride a relative). Check ride changes (`src/ride.js`, the will in `cellWGSL`) with both; docs/hand.md, Riding.
- `node tools/chronicle.mjs --n 131072 --minutes 60 --speed 16` runs the built page headless to a simulated time and prints the chronicler's stories, how many an hour, and every candidate it weighed (docs/chronicler.md). Check story changes with it: a few an hour, each one notable. `tools/ui-audit.mjs` and `tools/ui-check.mjs` also run headless on Linux with `TIDEMOTE_VK=1`.
- `desktop/` is the Electron app for Steam (its own package; `npm start`, `npm run package -- --platform win32`, `desktop/scripts/smoke.mjs`, `--steam 480`): saves as files for Steam Cloud, the Workshop, achievements from `src/achievements.js`; the page reaches it as `window.tidemoteDesktop`. docs/desktop.md. `.github/workflows/desktop.yml` builds it on each OS for every push to main (Steam's private `dev` branch) and every `v*` tag (Steam's `staging` branch, itch.io, a draft GitHub release), checked by `desktop/scripts/launch-check.mjs`; docs/release.md.
- `node tools/promo/editor/server.mjs` runs the promo video editor (http://localhost:8642); `tools/promo/` also films the shot library (`queue.sh`, `shoot.mjs`, `ui.mjs`, ... under `tools/gpu-node.sh`), catalogues it and renders drafts and the 4K master. Media and edits live outside the repo under `PROMO_ROOT` (`/mnt/d/tidemote-promo`); docs/promo.md.
- Fast speeds take coarse steps of up to 6/60 s (docs/fast-forward.md). An ecology change that touches `senseMain`, `lifeMain` (the two kernels of a living cell's step, both from `cellWGSL`: keep what each holds at once small, a phone's GPU runs out of registers; docs/performance.md, The step in two kernels), `cellWGSL`, `contactMain` or `resolveCount` should also keep 6-tick long runs (`ensemble.mjs --runs 128 --step 6`, or a farm with `--step 6`; `tools/fastforward/pool.mjs`) in line with normal ones.
- `lifeMain` also runs lean (`lifeMainLean`, `lifeMainCoarseLean`: the hand, annotations, dry ground, raindrops and duckweed compiled out by `IDLE_*` overrides, picked by `Engine._stepLean` only where this step's uniforms leave them idle; docs/performance.md, Lean step kernels). New code for something the world may leave idle goes under its override and into `_stepLean`'s test, and code gated by an `IDLE_*` must do nothing whenever `_stepLean` passes: `LP_NUM_THREADS=0 node tools/leancheck.mjs --cpu --n 4096 --steps 40 --warm 150 --ticks 2` (and 1, 6) compares lean and full bit for bit.

- `npm run text` starts the text editor (http://localhost:4711): every message, where it sits, rewritten as typed into `locales/en-x-rewrite.json` (docs/i18n.md). `npm run text:review` checks what was marked Done (structure, Harper's spelling and grammar) and `--list checked` prints it for a reader's review (`--approve`, `--note`); `npm run text:promote` writes approved rewrites into the source.

## Layout

- `src/shaders.js` all WGSL and `DEFAULT_K` (every tunable). WGSL's `pow` is undefined for a negative base (NaN, drawn black, on Metal and Vulkan; Windows' compiler turns `pow(x, 2.0)` into `x * x` and hides it): square with `sqr` (COMMON), and keep other bases non-negative. Likewise `atan2(0, 0)` is NaN on Metal (0 on Windows), and a NaN mixed in at weight 0 is still NaN: the observational shaders (INBOND, DRAW, POST, MICRO) take angles with `atan2z` (COMMON; 0 for a zero vector), since a still cell's NaN heading or squash, kept in its sway record, hid it whenever resolved (cells, dormant ones most, popping out as a Mac zoomed in); elsewhere nudge a possibly-zero vector before taking its angle. Chrome compiles Metal with fast math: `x != x` never finds a NaN, min/max/clamp/saturate swallow one, `tanh(x)` is NaN above about 44 (use `1 - 2 / (exp(2x) + 1)` or clamp x), `normalize` of a vector under about 1e-19 is infinite (a zero one NaN anywhere; `dirz` in COMMON), and `sin` of large arguments is coarse (sin-hashes differ from Windows). `tools/popzoom.mjs` (zoom steps on a held world, pops between them; `--bisect`) and `tools/popnan.mjs` (NaN in the records) check it.
- `src/engine.js` the WebGPU engine (buffers, passes, readbacks). The census only feeds naming and lineage tracking; nothing steers the ecology globally.
- `src/genome.js` CPU genome packing, archetypes, guild classification (`dietGuild`, `mobilityGuild`).
- `src/climate.js` seasons, climate eras (light, the water's temperature walk and its heat waves and cold snaps), abiogenesis rate: shared by the page and headless runs.
- Heat (docs/thermal-energy-2026-10-07.md): `heatMain` in `src/shaders.js` steps the water's temperature and its ice on the binning grid (`b.thermal`: deposits, then temperatures; ice is the water's phase with latent heat, so a frost's ice and the cold probe's are one and anything that warms the water thaws them, docs/catastrophes.md); every observational pass that shows heat (`DRAW_WGSL`, `POST_WGSL`, `LISTEN_WGSL`) reads it with the default tunables (`shownThermal`). The page opens with `DEFAULT_K` overrides from a `#k={...}` URL hash.
- The storm's sea (docs/catastrophes.md): `src/sea.js` (layout, spectrum; tested) and `SEA_WGSL` (an FFT ocean the size it would be, fixed in the world; `seaSurface` in the post pass bends the view, focuses caustics and tilts a sheen). Check changes with `tools/waterlook/gpucheck.py` through looklab (the sea drawn alone: `eng.seaTune.view` 1 its light, 2 its sheen) and film them with `tools/waterlook/zoomclip.mjs`; `tools/waterlook/edgecheck.mjs` measures how much the bend stretches the frame's edge against its inside (`keepInFrame`).
- Stone's look (docs/look.md, Stone): `vsStone`/`mineralSurf`/`fsStone` (two passes, a grain then its edge) and `boulder`/`stoneShade`, lit once into a cache (`fsStoneCache`, drawn again only when `_stoneStale` in `src/engine.js` says: the view left it or zoomed past it, a new world, selection, focus or setting, or every half second while the world runs) and put under the cells each frame by `fsStoneLit` into the scene the composite, the bloom, the loupe and the close-up read (so the optics and the look take stone as they take cells); anything stone shows that changes must make the cache stale. `tools/stonelab.mjs --out runs/stone/NAME` (`TIDEMOTE_VK=1 tools/capped.sh`) photographs the same grains of one saved world at each zoom and look (`--html` an older build, `--loupe 1` the loupe too, `--at x,y` a point of your own (a framboid), `--shift 1` frames for `tools/stonelab-shimmer.py`, how much it shimmers as the view moves); check stone changes against a run of the previous build, from afar too.
- The look (docs/look.md): `src/look.js` (Darkfield's tunables; tested) and `Post.look`, applied in the composite, the loupe and the close-up (specimen viewer, card portraits: `fsPlain`) by `lookScene`, `lookTone`, `lookGrade`/`lookDisplay`; Settings → Display scales it (Microscope) and sets its grain (`applyLook`), `T.look.set(p, strength)`/`T.look.off()` from tools, `look: "on"|"off"` in a perf plan's scenario. The world's light lights the scene in the composite and the loupe (`sceneLit` mirrors `lightAt`; `litGain` stronger on stone, silt and the floor than on the living, told apart by the living's layer, which the splat fills too; the sea's focusing on the grains (`FOCUS_*`), the living's shadows, silt's sparkle (`sunAt` in DRAW_WGSL, the light in the view's uniforms), the look's bloom, halation, veil, rims and a golden grade (`SUN_*`, `lookScene`'s `sun`); docs/look.md, Light): change it with `lightAt`. The murk is three layers at depths that pan slower than the cells but never move on a zoom (`Engine._murkCam`; docs/look.md, Murk).
- How a world starts (`found*` in `DEFAULT_K`, `seedMain`, `randomGenome` mirroring `randomInto`): docs/founding.md. `tools/startlab.mjs` grows fresh or saved worlds (Dawn, or `--chrome`), can cull most life at a moment, and records diversity, lineages and spatial turnover; `tools/startlab-report.mjs` compares groups of runs.
- `src/headless.js` the headless frame loop, run under Dawn or inside Chromium; `src/ecostats.js` run and ensemble metrics and the statistical comparison.
- `src/audio/` the soundtrack: a sample-level JS port of SuperCollider UGens and voices (`ugens.js`, `voices.js`) driven by `conductor.js` in an AudioWorklet; `sound.js` is the main-thread controller; `field.js` turns the GPU listening scan (`LISTEN_WGSL`, observational) into notes. Tune it offline with `tools/listen-capture.mjs` + `tools/listen-render.mjs`; `tools/listen-score.mjs` measures repetition and how worlds' openings differ (each world's music is keyed by `climate.music`, its seed). Check changes to `ugens.js`/`voices.js` against SuperCollider with `tools/audio-parity/` (sclang as root needs `QTWEBENGINE_DISABLE_SANDBOX=1`).
- `src/audio/mix.js` the viewer's mix (Settings → Audio: each layer's level, space, tone, playing while hidden; pure, `test/mix.test.js`): the audio thread scales each voice by its layer (`Engine.groups`; the conductor tags `grp` on what it schedules, by the part that runs: `MSG_LAYER`, `bar`, the hand's tick), Space multiplies the reverb's decay and share, Tone the master's low-pass and high shelf. The default mix renders the same samples as none; render audio tests at 48 kHz (the master's tone sits above a lower rate's Nyquist).
- `src/audio/motif.js` each species' song from its genome (pure, tested in `test/motif.test.js`); `src/song.js` draws it (piano roll; sigil, the song drawn as its organism). `tools/sigil-gallery.mjs` shows sigils beside species portraits from `tools/species-portraits.mjs` (a headless trial world drawn to an offscreen texture). Compare generators by ear and by numbers with `node tools/motif-gallery.mjs --out gallery --legacy`. `mutateLike` in `genome.js` mirrors the GPU's `mutateInto` for tools and tests only.
- `src/mind.js` names what the selected cell is doing (hunting, fleeing, grazing...) from `mindMain`, an observational replay of its last `lifeMain` step; `src/mindview.js` draws it in the specimen panel (built once per cell, updated in place, compass eased per frame). Both kernels share `cellWGSL` in `src/shaders.js`; its recording hooks must expand to nothing in `lifeMain` (`test/mind.test.js` checks).
- Cell events (births budding, deaths withering or bursting, bites, meals, cysts, new species sparkling) are animated from a per-cell record `contactGather` keeps (`ANIM_WGSL`, `animOf`/`ghostOf` in DRAW_WGSL), observational only; docs/animation.md. Film them close up with `tools/anim/film.mjs` (`--hunt births`, then `tools/anim/crop.mjs`/`hcrop.mjs` for frame strips).
- `src/chronicler.js` the chronicler: natural history for the log from the census and the species ledger (`SPL_*` in `src/shaders.js`, at the ledger buffer's end, observational: per-slot births and deaths by cause, tries and meals between the `SPL_WATCH` watched species, `rangeMain`'s sample of where each species is), told rarely under a budget (`TUNE`); pure, tested in `test/chronicler.test.js`; docs/chronicler.md. `src/card.js` species cards, laid out as trading cards (portrait from one frame of the close-up renderer, sigil, record, gauges of body, diet and water, the chronicler's line, QR; PNG, and a WAV of the song from `songClip` in `src/audio/sound.js`, the worklet rendered offline) and the viewer's own names (`sp.given`, kept in saves). `src/film.js` records the view until stopped (MediaRecorder, captions burned in; written to disk as it is made where it can, the desktop's Videos folder or the browser's private files, else in memory; its limit from where it goes), `src/webm.js` mends the WebM as it streams (duration, Cues; tested); docs/film.md. Measure it with `TIDEMOTE_VK=1 tools/capped.sh -m 900M node tools/film-check.mjs --size laptop|phone|4k --minutes N` (MB a minute, memory, ffprobe, a seek's bytes; `--memory`, `--cap BYTES`), and how it looks with `tools/film-quality.mjs` (SSIM/PSNR of decoded frames against lossless originals, found by a barcode).
- The hand (docs/hand.md): `src/hand.js` the tools and the engine's hand words (`Hand` in `simWGSL`'s `Sim`: lamp, stage, the rod, the needle's cut and shaft, the ridden cell's will, the pipette's draw; `handPush` sweeps from where the needle and rod were when the world last stepped), zero in every headless run, and the instrument seen in the water (`eng.tool`, the composite's `instrument`); `src/bench.js` the dock's tools, the Bench drawer and the phone's held strip; `src/ladder.js` the speed ladder (held and dragged, or scrolled); `src/pipette.js` the pipette's contents (`life.pipette`; drawing up and setting down use the ledger's hand region, `PIPE_*` and `inject*` in `src/shaders.js`); `src/cabinet.js` a card's genome payload (PNG text chunk, QR link) and the cabinet's store, `src/qr.js` the QR encoder; `src/minicard.js` the mini-cards of the strip and the cabinet, `src/studio.js` their portraits drawn alone (`setStudio`), and `src/studiorender.js` the card page's (a card's link opened: the card at once, then its portrait from a device of its own with only the studio's pipelines; `test/linked.test.mjs` drives the page, run it after changing the card, the studio's shaders or `viewWords`); `src/audio/handsound.js` the hand heard in the soundtrack. The hand's acts are the world's record (`life.hand`, in saves) and the chronicler tells them as weather.
- `src/director.js` the auto camera: shot planning over the observational survey (`SURVEY_WGSL`), smooth zoom-and-pan paths; pure, tested in `test/director.test.js`.
- Live annotations (docs/annotations.md): notes over the view on what is happening in it (hunts, grazing, scalding, the cold, blooms, new species), with the auto camera by default (Settings → Annotations). The steps write each event in the page's `sim.watch` rect where it happens, doer and all (`note`/`noteBy`/`noteSelf`, a ring at the ledger's end, `NOTE_*`; masked by `sim.watchEv`), and `NOTE_WGSL` reads back the view's cells every few frames, both observational and their own readbacks (never a pick); `src/notes.js` finds the stories and keeps the attention budget (pure, `test/notes.test.js`), `src/noteview.js` draws them on the overlay (so films keep them; stretches of the world as organic shapes from `src/contour.js`; magnified within the loupe). Film them with `tools/gpu-node.sh tools/notes-live.mjs --out runs/notes/NAME` (`--audit`: how steadily they ride the scene and any overlapping text, `src/noteaudit.js`; check label or mark changes with it).
- `src/worlds.js` saved worlds (Settings → Worlds): `eng.readState()` plus the page's record (species registry, chronicle, history, climate eras, camera) as one gzipped file in IndexedDB, downloadable as `.tidemote`. A change to what `readState` keeps or to a buffer's layout (`P_BYTES`, `G_BYTES`, ...) makes old saves refuse to load (sizes are checked); bump `SAVE_VERSION` (semver, `src/worlds.js`; docs/desktop.md) with every format change: major when old saves can no longer load, minor for additions older versions can ignore. A save keeps the particles and intents by columns, floats cut (`compactState` in `src/engine.js`: its per-word `keep`/`planes` follow `struct Particle` and its heat blocks the `thermal` layout, so change them with them; it gives silt new ids, so a silt grain's id must stay meaningless beyond random draws and drawing); `tools/fork.mjs` variants `{"kept":true}` check a saved world runs on like the original. The page's record (life, climate, chronicle) goes through `pack`, which brings every value back exactly (Maps, Sets, typed arrays, Infinity/NaN, an object held in two places as one) or throws on saving, naming the field; keep the page's own settings (like `climate.allowed`) out of it. An error in a frame shows the error screen (`fail` with actions in `src/main.js`) rather than stopping the loop silently.
- Worlds run for days (left on a TV, at Max): nothing may grow with time or lose precision. `pruneRecords` in `src/main.js` keeps the species registry, genera and orphan lines to what can still be shown or reached; times sent to the GPU are wrapped (simulated time modulo `SIM_CLOCK` with the tide's and currents' phases folded in on the CPU, real time modulo 4096 s), a genome's `born` is on that clock (`clockDiff` in WGSL, unwrapped when a species registers); the GPU's u32 counters are differenced `>>> 0`, and particle ids wrap past `NONE` (`newId`). Keep new state, clocks and counters to these patterns.
- The page's words (docs/i18n.md): every string a visitor reads (text, `aria-label`, `data-hint`, alt, placeholder, canvas `fillText`, flashes, errors shown on the page) is a message, so the viewer can rewrite it in the text editor and it can be translated. When you add or change copy:
  - In JS write `tr('area.thing', 'Source text with {x}', { x })` (`import { tr } from './i18n.js'`; ICU MessageFormat: `{n, plural, one {# cell} other {# cells}}`, `{k, select, a {...} other {...}}`, inline `<b>`/`<kbd>`, other tags passed as functions). The id and text are literals. Ids: `area.thing[.part]`, lowercase, `-` between words, named for the purpose, never the words; an existing message whose English changes keeps its id. Tables of labels are built at load with `tr()`. Never name a local variable `tr`.
  - In `src/page.html` mark the element `data-i18n="area.thing"` (its attributes become `area.thing.aria`, `.hint`, `.alt`, `.ph`, `.title`).
  - Whole sentences with arguments, never glued fragments; articles, plurals and capitals in the message (write the HUD's capitals as capitals), never `toUpperCase()`/`a`-vs-`an` in code; logic never compares displayed text. A plural's `#` groups digits (1,234) where a plain `{n}` does not: keep what the old text printed.
  - Say what each argument is in a comment holding `i18n:` on the line or two above (the editor and translators see it).
  - Then `node tools/i18n/extract.mjs` and commit `locales/en.json` with the change. `test/i18n.test.js` fails on a stale en.json, a call that does not supply its arguments, and prose outside `tr()` (`--audit` lists it); the audit is heuristic and misses single words and short labels, so check every visible literal yourself. Not messages: species and genus names, ids, keys, console output, developer errors, WGSL, headless tools (`// i18n-ignore` on a line the audit flags wrongly). A new id area gets a name in `AREAS` (`tools/i18n/textlab/app.js`).
- `src/main.js` the page; `names.js`, `facets.js`, `trace.js`, `flow.js` are its pure helpers; `specimen.js` the specimen panel, `lab.js` the Field Lab, `tip.js` the hints. Styles live in `src/page.css`. Build panel markup from `src/ui.js` (section and block headings, blocks, labeled rows, disclosures) and space it with the `--s1`…`--s5` scale rather than adding new header or row styles; keep live rows at fixed heights so updates never shift what is below them. UI text and glossary terms carry `data-tip`/`data-hint`, never `title` (it fights the hints). Panels update in place (never re-render a control under the pointer) and a pointer click hands focus back so shortcuts keep working.

## Headless caveats

- On Linux without a display (an NVIDIA GPU), `TIDEMOTE_VK=1 node tools/ensemble.mjs --chrome ...` (and `sim.mjs --chrome`, `tools/perf/bench.mjs --linux`) runs Chromium on the GPU through Vulkan (`tools/vk.mjs`). It needs NVIDIA driver 595 or later (Ubuntu 26.04), whose Vulkan has `VK_EXT_headless_surface`. The 32-seed gate takes about 20 minutes there and matches the D3D12 baseline.
- Under WSL, prefix headless tools with `tools/gpu-node.sh` (Windows Node, Dawn on D3D12, the real GPU). Plain `node` in WSL only finds llvmpipe, and `sim.mjs`, `fork.mjs`, `swimlab.mjs`, `steplab.mjs` and `ridelab.mjs` refuse it unless `--cpu` is passed (`tools/adapter.mjs`).
- `tools/capped.sh [-m SIZE] command...` caps a command's memory (a browser that runs away is killed, not the machine): through `~/.local/bin/capped` where a machine has it, else a user systemd scope (`MemoryMax`, no swap), else uncapped with a warning.
- GPU runs are not bit-reproducible per seed; compare ensembles, never single runs.
- On machines without a GPU use `--chrome` (Playwright Chromium with SwiftShader). It is slow (about 76 ms/frame at 4k particles) but stable.
- The Dawn path (`webgpu` npm, `--cpu` for lavapipe) is for real GPUs. On Mesa lavapipe it aborts after a few thousand frames whenever async readbacks are used; do not try to work around it with pacing tricks.
- Every ecological rule is local (see README "How the simulation works"); do not add census-driven regulators back.

## Waiting on long runs (gates, farms, ensembles, sims)

- Never wait with `pgrep -f`/`pkill -f` on a pattern like `farm.mjs`, `sim.mjs` or `until`: the waiting loop's own command line (and other sessions' loops) contains the pattern, so `pgrep -f` never comes back empty (a finished run looks unfinished forever) and `pkill -f` kills the waiter itself and other sessions' waiters.
- Start the run itself with `run_in_background` (its log redirected into its `--out` dir) and let its exit be the notification; no separate wait loop. If one is needed, wait on the PID (`while kill -0 PID; do sleep 30; done`), and stop a run only with `kill PID` (SIGINT for `farm.mjs`, which stops its sims on every host).
- A run is done when its log prints the summary (`NAME: 32 runs × 30 min at n=...`, then `Against baseline` when gated), not when processes vanish. Check that line, or count the run JSONs in `--out`.
- Start several farms one after another, a few seconds apart: started together, they race to push the same `refs/farm/SHA` and the losers drop that host.
